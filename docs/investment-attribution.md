# 盈亏归因

持仓明细下方展示横向正负条形图。默认「全部」，可切换「已平仓」「持仓中」；同时遵循顶部账户和框架筛选。相同证券代码合并显示、按盈亏金额降序排列。币种为 USD，绿色盈利向右、红色亏损向左。三种状态共用线性金额轴与等距刻度，筛选时不缩放金额尺度。底部图例固定为「盈利 / 亏损」，悬停与图表键盘导航可查看证券代码及精确金额。

复用 BoardUI ChartCard、ChartLegend、ButtonGroup / ButtonGroupItem，筛选以 `aria-pressed` 和强调背景标记唯一选中项。注册表 BarListCard 仅支持非负占比，无法表示零轴两侧金额，因此绘图区使用 Recharts 线性横向 BarChart。小屏在图表内部横向滚动，避免压缩金额轴；辅助技术可读取完整数据表。柱条零轴端为直角，仅外端圆角；柱条、图例与浮层金额统一使用 `chart-return-positive` 盈利色。亏损使用 `chart-attribution-loss`，基于热力图亏损色混入中性文字色，降低饱和度并加深，自动适配深浅色模式。浮层采用内容宽度、紧凑四行布局，保留全部信息。

持仓中的盈亏来自 `positions[].pnlAmount`，仅纳入股数大于零的当前持仓。缺少该字段时不以 `totalReturn` 替代。新增可选 `closedPositions[]`，每条包括：

- `symbol`：证券代码；`name`：可选名称。
- `pnlAmount`：截至模块快照日的已平仓已实现盈亏，USD，有限数值或 null。
- `pnlPct`：可选同口径盈亏百分比，25 表示 25%；`buyInAmount`：可选原始成本金额（USD）。
- `accountId`、`inFramework`、`bucket`：可选归属，与持仓一致。

已平仓记录由数据提供方填写，不根据股数为零推断。各条应覆盖互不重叠的已平仓批次，避免重复计入。归因金额为价差盈亏；分红等额外回报不在该口径内。「全部」将当前未实现盈亏与已平仓已实现盈亏相加；同一标的任一记录缺失金额时，整项显示缺失并不绘制不完整合计。真零仍保留。

`closedPositions` 缺失表示尚未接入已平仓数据，界面明确提示；空数组表示已提供但无记录。不会修改或补造用户数据、示例交易。缺少账户或框架归属的记录不猜测归属，筛选时提示仅展示已匹配标的。

悬停提示展示证券代码、平仓状态、盈亏金额和盈亏比例。同一标的同时含两类记录时，状态显示「持仓中 / 已平仓」。单条记录优先使用 `pnlPct`；缺失但存在正成本时可用金额 / 成本计算。多条记录只在金额与各条正成本均完整时按合计金额 / 合计成本计算，不累加或平均百分比。无可用比例显示「—」，真实零显示 0%。
